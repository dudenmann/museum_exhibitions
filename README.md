# Сервис учета музейных выставок

Учебный индивидуальный проект. Текущий этап — подготовительная консольная
версия перед ПР5. ПР5, ПР6 и ПР7 еще не выполнены.

Программа хранит залы, кураторов и выставки, позволяет планировать и отменять
выставки, искать их по названию и находить свободные залы на период.
Демонстрационные имена и данные вымышлены.

## Запуск в Windows PowerShell

На этом компьютере окружение создано на Python 3.12.10. В PDF пример использует
Python 3.11; фактическую версию окружения в отчетах будем указывать честно.
Для этой консольной версии сторонние библиотеки нужны только для проверок.

```powershell
cd D:\codex-111\museum_exhibitions
.\.venv\Scripts\python.exe main.py
```

Активация окружения не требуется: команды явно вызывают Python из `.venv`.
При переносе проекта на другой компьютер окружение создается заново:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

## Как пользоваться

1. Пункт 1 показывает залы и их ID; пункт 2 — кураторов.
2. Пункт 3 показывает все выставки, включая отмененные.
3. Пункт 6 ищет свободные залы на период. Даты вводятся как `2026-11-05`.
4. Пункт 4 создает выставку: нужны название, ID зала, ID куратора и даты.
5. Пункт 5 отменяет выставку по ID и освобождает зал.
6. Пункт 7 ищет неотмененные выставки по части названия без учета регистра.
7. Пункты 8 и 9 добавляют залы и кураторов. Пункт 0 завершает работу.

Для проверки на исходных данных найдите свободные залы с 2026-11-05 по
2026-11-10: свободен только Исторический зал (ID 3). Выставка в нем отменена.
Попытка создать выставку в Главном зале (ID 1) на эти даты будет отклонена.

Слово «неотмененная» не означает «проходит сегодня»: в списке есть и будущие,
и прошедшие выставки. Даты обеих границ включены: если выставка заканчивается
10 ноября, следующая в этом зале может начаться 11 ноября.
Каждая выставка занимает один зал; куратор может вести несколько выставок.

## Устройство проекта

| Файл | Назначение |
| --- | --- |
| `models.py` | Классы Hall, Curator, Exhibition и проверки их полей |
| `services.py` | Создание, отмена, поиск, доступность залов и проверка связей |
| `storage.py` | Преобразование объектов в JSON и обратно, сохранение |
| `main.py` | Меню, ввод и вывод; вызывает готовые сценарии |
| `data/demo.json` | Исходный набор: 3 зала, 2 куратора, 4 выставки |
| `data/local.json` | Рабочие данные; создаются при первом изменении |
| `tests/test_project.py` | Проверки правил и сохранения данных |

Один JSON-файл хранит три коллекции. Это осознанная адаптация примера методички:
связанные данные сохраняются одной атомарной заменой файла. В ПР7 каждая
коллекция станет отдельной таблицей, а этот JSON будет источником импорта.
Поврежденный файл не заменяется пустыми данными: программа сообщает об ошибке.
Рабочий JSON исключен из Git, демонстрационный хранится в репозитории.
Одновременная запись из нескольких процессов на этом этапе не поддерживается.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m pytest -v
.\.venv\Scripts\python.exe -m flake8 .
```

Тесты используют временные файлы и не изменяют рабочие данные.
Проверяются пересечения дат, их границы, освобождение зала после отмены,
отсутствующие связанные записи, поиск, перенос объектов в JSON и обратно,
поврежденный JSON и повторяющиеся идентификаторы.
