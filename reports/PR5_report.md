## 1. Цель работы

Создать веб-интерфейс индивидуального проекта на Django, настроить обработку
HTTP-запросов и маршрутизацию, сохранив объектную модель и JSON-хранилище.

## 2. Исходное состояние и средства разработки

Для проекта подготовлена консольная основа: классы `Hall`, `Curator`,
`Exhibition`, создание и отмена выставок, проверка занятости залов,
JSON-хранилище и автоматизированные тесты. Выставка связана с одним залом
и одним куратором. Две неотмененные выставки не могут занимать зал
в пересекающиеся даты; обе границы периода включены.

Использованы Python 3.12.10, Django 5.2.18, HTML, CSS, pytest, flake8 и Git.
Python 3.12.10 — фактическая версия окружения; пример PDF использует 3.11.
Работа выполнена в существующем репозитории `museum_exhibitions`.

## 3. Доработка индивидуального проекта

Создан Django-проект `museum_site` и подключены приложения `homepage`,
`halls`, `exhibitions`. В корневом `urls.py` маршруты распределены между
приложениями через `include`; в приложениях определены обработчики страниц.

| URL | Назначение |
| --- | --- |
| `/` | Главная страница |
| `/halls/` | Список залов |
| `/halls/<int:item_id>/` | Карточка зала |
| `/halls/available/` | Поиск свободных залов по началу и окончанию периода |
| `/exhibitions/` | Список выставок |
| `/exhibitions/<int:item_id>/` | Карточка выставки с залом и куратором |

Обработчик получает данные через `load_museum()` и формирует HTML-ответ
функцией `page()`. Конвертер `int` извлекает ID из адреса. Отсутствующий
объект вызывает `Http404`, некорректный период поиска возвращает HTTP 400,
успешная обработка — HTTP 200. Настроена пользовательская страница 404
для режима `DEBUG=False`.

Между страницами организована навигация. Оформление задано собственным CSS;
Bootstrap не подключался. Текст из данных экранируется через `escape()`.
На этом этапе HTML формируется в Python, данные остаются в JSON;
Django ORM и SQLite для предметных данных еще не используются.
README дополнен структурой веб-части, URL и командой запуска.

## Приложение А. Фрагменты кода вместо скриншотов

Листинги взяты из состояния `PR5`, а не из более поздней SQL-версии.

### А.1. Маршруты приложения halls

Файл `halls/urls.py`. Маршруты списка, поиска и карточки разделяют
сценарии, а именованный параметр передается в представление.

```python
from django.urls import path

from . import views

app_name = "halls"
urlpatterns = [
    path("", views.index, name="list"),
    path("available/", views.available, name="available"),
    path("<int:item_id>/", views.detail, name="detail"),
]
```

### А.2. Получение карточки и ответ 404

Файл `halls/views.py`. Загружается существующая JSON-модель; отсутствующий
ID преобразуется в HTTP-ошибку, описание экранируется перед выводом.

```python
def detail(request, item_id):
    try:
        item = load_museum().get_hall(item_id)
    except ValueError as error:
        raise Http404 from error
    return page(item.name, f"<p>{escape(item.description)}</p>")
```

### А.3. Проверка доступности зала

Файл `services.py`. Отмененные выставки исключаются методом `overlaps`.
Сравнение начала и окончания защищает сценарий от неверного периода.

```python
def available_halls(self, start: date, end: date):
        if start > end:
            raise ValueError("Дата окончания не может быть раньше даты начала.")
        occupied = {
            item.hall_id for item in self.exhibitions if item.overlaps(start, end)
        }
        return [hall for hall in self.halls if hall.id not in occupied]
```

## Приложение Б. Дополнение по общему заданию Word

В итоговой версии `3414d79`, после этапов PDF, серверная часть дополнена
REST API: GET/POST для выставок, залов и кураторов, GET/PATCH для карточки
выставки. Создание возвращает 201, отмена сохраняет запись в истории.
API документирован в [API.md](../docs/API.md).

Созданы учетные записи с ролями `viewer` и `editor`. На сервере проверяется
право изменения, пароли хешируются, запросы защищены CSRF, SQL-значения
передаются параметрами. Интеграционные тесты проверяют отказ анонимному
пользователю и роли просмотра, успешную запись редактора, конфликты дат.
Сводная статистика кэшируется на 30 секунд: первый вызов выполняет
4 SQL-запроса, повторный — 0; после записи кэш сбрасывается.
В итоговой версии успешно выполнены 48 тестов.

Файл `accounts/security.py`, итоговая версия: права проверяются не только
видимостью кнопки, но и перед выполнением серверной операции.

```python
def editor_required(view):
    @wraps(view)
    def wrapped(request, *args, **kwargs):
        account = current_account(request)
        if account is None:
            if request.path.startswith("/api/"):
                return JsonResponse({"error": "Необходимо войти."}, status=401)
            return redirect("accounts:login")
        if account["role"] != "editor":
            return JsonResponse({"error": "Нужна роль редактора."}, status=403)
        return view(request, *args, **kwargs)
    return wrapped
```
