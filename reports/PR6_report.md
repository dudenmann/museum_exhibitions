## 1. Цель работы

Перевести веб-интерфейс проекта с формирования HTML в Python на шаблоны
Django. Применить наследование, включаемые фрагменты, контекст, циклы,
условия, фильтры, именованные URL и статические файлы.

## 2. Исходное состояние

Использована версия ПР5: Django-проект `museum_site`, приложения `homepage`,
`halls`, `exhibitions`, объектная модель музея и JSON-хранилище.
До переработки HTML создавался функцией `page()` непосредственно в Python.
Среда: Python 3.12.10 и Django 5.2.18.

## 3. Доработка индивидуального проекта

Общий каталог `templates` подключен через `TEMPLATES['DIRS']`,
`APP_DIRS=True` обеспечивает поиск шаблонов приложений. Создан `base.html`
с блоками `title` и `content`. Дочерние страницы наследуют его через
`extends`. Навигация и карточки вынесены в `templates/includes`
и подключаются тегом `include`.

Представления теперь выбирают объекты, формируют словарь контекста и
вызывают `render()`. Данные сохраняются в JSON; классы и бизнес-правила
не перенесены в HTML. Функция `page()` больше не вызывается веб-частью.

| Элемент | Применение в проекте |
| --- | --- |
| `for`, `empty` | Карточки коллекции и сообщение при пустом результате |
| `if` | Статус отмены, ошибки поиска и условия отображения |
| `date`, `default`, `truncatechars` | Формат дат, замена пустого описания, сокращение текста |
| `length`, `stringformat` | Количество элементов и формат номера карточки |
| `app_name`, `url` | Именованные ссылки с пространствами имен приложений |
| `load static`, `static` | Подключение CSS, SVG-логотипа и JavaScript |

Сохранены главная страница, списки и карточки залов/выставок, поиск свободных
залов и 404. Созданы общий визуальный стиль, адаптивная сетка карточек,
мобильное меню и подсветка активного пункта. Поиск выставок получает
параметр `q`; пустая выборка выводит понятное сообщение. Автоматическое
экранирование шаблонов сохраняет текстовые значения безопасными для HTML.
README обновлен с учетом новой структуры.

## Приложение А. Фрагменты кода вместо скриншотов

Листинги относятся к метке `PR6`. Переносы строк в HTML для чтения
не изменяют используемые теги и выражения.

### А.1. Представление и контекст

Файл `exhibitions/views.py`. Один словарь связывает Python-объекты
с переменными шаблона; источник данных еще JSON.

```python
def detail(request, item_id):
    museum = load_museum()
    try:
        item = museum.get_exhibition(item_id)
    except ValueError as error:
        raise Http404 from error
    return render(request, "exhibitions/detail.html", {
        "item": item, "hall": museum.get_hall(item.hall_id),
        "curator": museum.get_curator(item.curator_id),
    })
```

### А.2. Базовый шаблон

## Приложение Б. Дополнение по общему заданию Word

В итоговой версии `3414d79` клиентская логика дополнена формами `/workspace/`
для создания выставки, зала и куратора. JavaScript перехватывает отправку,
собирает JSON и выполняет `fetch`. Сервер проверяет данные и права.
При успехе открывается карточка либо обновляется страница; сообщение
об ошибке выводится через `textContent`. Кнопка временно блокируется,
чтобы уменьшить риск повторной отправки. Отмена требует подтверждения.

Фрагмент `static/main.js`: сессия отправляется только на тот же источник,
а CSRF-токен читается из скрытого поля формы.

```javascript
const response = await fetch(form.action, {
      method, credentials: 'same-origin',
      headers: {'Content-Type': 'application/json',
        'X-CSRFToken': form.querySelector('[name=csrfmiddlewaretoken]').value},
      body: JSON.stringify(data),
    });
```

Интеграция и защита проверены серверными тестами: успешное создание,
отказ без CSRF, запрет роли просмотра, отмена и повторное использование
зала. Итоговый набор — 48 успешных тестов. Полный клиентский сценарий
в реальном браузере отдельно не подтвержден автоматизированным прогоном.
Документация запросов: [API.md](../docs/API.md).
