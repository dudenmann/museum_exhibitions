# Локальное развертывание

HTTP на 127.0.0.1:8000, Waitress для WSGI, WhiteNoise для static, DEBUG=False.
Подготовка и запуск — в README. Сервер запускается вручную текущим пользователем
Windows. Автозапуск и непрерывный внешний мониторинг не настроены.
Правила брандмауэра не менялись; сокет привязан только к loopback.

## Безопасность и наблюдение

Секрет генерируется в .secret-key и исключен из Git. Разрешенные Host:
localhost и 127.0.0.1. Сессия — подписанная cookie Django, HttpOnly, SameSite=Lax,
срок один час. Предметные данные и аккаунты используют sqlite3, без ORM.
Копия подписанного cookie может действовать до истечения часа даже после выхода:
глобального отзыва сессий в учебной версии нет.

Пароли хранятся в виде хешей. Случайный исходный пароль записан в
data/local-access.txt: файл не публиковать. Права записи требуют роль editor.
Дополнительный пользователь для просмотра:

```powershell
.\.venv\Scripts\python.exe -m scripts.create_account viewer --role viewer
```

Для редактора укажите другое имя и --role editor. Пароль вводится скрыто,
минимум 12 символов. Открытые страницы доступны и без входа; viewer показывает
запрет записи для вошедшего пользователя.

Журнал logs/museum.log ротируется: 1 МБ, три резервных файла. В нем метод,
путь, код ответа и длительность. Пароли, cookie и тела запросов не записываются.
/health/ проверяет доступность таблицы exhibitions и возвращает 200 или 503.

```powershell
Invoke-RestMethod http://127.0.0.1:8000/health/
.\.venv\Scripts\python.exe manage.py check --deploy --settings=museum_site.deploy
```

Check --deploy оставляет W004, W008, W011, W016: HSTS, переход на HTTPS и
Secure-cookie не включены для localhost по HTTP. Предупреждения не скрыты.
Для публикации в интернете потребуются HTTPS и пересмотр конфигурации.

## Перенос и резервирование

После изменения static выполните collectstatic; после изменения Python
перезапустите сервер. Рабочую базу с аккаунтами и секретами не публикуйте.
Для сдачи ПР7: docs/submission/pr7-demo.sqlite3 — предметные таблицы и demo-данные
без аккаунтов. Все SQL-файлы и код импорта находятся в репозитории.

Резервную копию рабочей SQLite-базы делайте при остановленном сервере либо
через SQLite backup API. JSON — исходный набор импорта, а не резервная копия
текущего веб-приложения.
